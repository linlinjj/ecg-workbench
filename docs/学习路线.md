# 边学边做：从一个采样点到完整工作台

不要先背全部框架。每次选一个可观察的小目标，读代码、改一个参数、运行检查，再解释结果。

## 1. 理解数据（约 1 小时）

打开 `public/samples/100.json`，找到 fs、sampleCount、channels、reference 和 provenance。
计算：360 Hz 下，第 360 个采样点是第几秒？21600 个点有多长？通道名和单位为什么不能丢？
运行示例、切换导联，核对这些数值与界面。不要修改数据来源和参考标注来让界面“更好看”。

## 2. 理解界面状态（约 1—2 小时）

从 `src/App.tsx` 的 record、channel、view、history、draft/applied 读起。
目标：说清楚哪些操作改变原始数据，哪些只改变视图。答案是当前所有交互都保留原始数据；滤波生成新数组。
试着修改一条帮助说明并运行 `npm run dev`，观察热更新。

## 3. 理解波形与坐标（约 2 小时）

阅读 `Waveform.tsx` 与 `project.ts` 中的 limitView / envelope。
把“屏幕上的 x 坐标 → 采样索引 → 秒数”的转换写在纸上。缩小查看整段信号时，用保留极值的显示抽样保住峰值；计算仍使用完整信号。
标记一个心搏，改变缩放后确认标记指向同一个采样点。

## 4. 理解滤波（约 2 小时）

阅读 `public/python/dsp.py`。先理解采样率的一半，再理解高通、低通和陷波。
使用人工加噪示例分别只启用高通、低通、50 Hz 陷波，观察哪些干扰减少、哪些波形变化。
不要把“更平滑”直接等同于“更真实”。离线双向滤波也有边界效应。

## 5. 理解标注和可撤销操作（约 2 小时）

查看 Annotation 与 History：每次操作产生新的数组，past / present / future 记录状态。
点标注存 start，区间标注存 [start, end)，同时记录通道。参考标签单独存储，不能被个人编辑覆盖。
运行组件测试，观察添加、备注编辑、撤销、重做、删除是否都能解释。

## 6. 理解导入、导出和验证（约 2 小时）

完整项目包是 ZIP，包含 manifest.json 与 record.json。用普通压缩软件查看：为什么有版本号、来源和哈希？
运行 `npm test` 后再运行 Python 测试，理解同一个项目包如何从 TypeScript 导出，再由 Python 重新读取。
最后运行 WASM 对照，区分“公式看起来相同”和“对同一输入实际得到相同数值”。

## 7. 准备后续迭代

先实际使用，记录至少三个卡点。后续候选包括键盘快捷标注、更多 WFDB 变体、信号质量检查，再考虑自动心搏检测和经过验证的分类模型。新功能应有明确用户与可重复的验收场景。
